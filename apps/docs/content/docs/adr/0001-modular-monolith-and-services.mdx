# 0001: NestJS modular monolith + Python AI services

**Status:** Accepted · 2026-10-22

## Context
Six engineers, seven weeks, 126 requirements. Microservices would multiply deploy, network and auth surface. AI work (proxy streaming, LLM SDKs, evals) is strongest in Python.

## Decision
- `apps/api` and `apps/worker`: one NestJS codebase, modules per bounded context, strict module boundaries (lint-enforced imports).
- `services/ai-proxy` and `services/reviewer`: separate Python services. The proxy is isolated because it holds provider keys. The reviewer is isolated because it processes hostile content.
- `apps/web`: Next.js.

## Consequences
+ One deploy unit for most business logic, simple transactions, fast for agents to navigate.
+ Security-critical surfaces (keys, untrusted content) are isolated in their own processes and IAM roles.
− Must police module boundaries to keep the monolith splittable later.
