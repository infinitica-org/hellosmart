# HelloSmart.ai Engineering & Product Portal

Welcome to the internal engineering and product documentation for **HelloSmart.ai**. HelloSmart is an AI-native hiring platform—*"Hire by doing."*

Candidates solve real problems with AI co-pilots inside sandboxed Sysbox containers. Independent AI reviewer agents score candidate submissions against explicit rubrics with exact evidence citations, while human hiring managers make the final decision.

---

## Developer Onboarding: Quickstart Guide

Follow these steps to get up to speed with the repository and architecture:

### 1. Understand the Product Loop ("Hire by Doing")
Read **[The Product in 60 Seconds](/docs/knowledge-base/00-start-here)** and the **[Core Concepts](/docs/knowledge-base/02-core-concepts)**. HelloSmart assesses candidates by having them perform real work with AI tools in sandboxed Sysbox containers, evaluated by independent reviewer agents with human hiring managers in final control.

### 2. Review the 33 Inviolable Business Rules
Read the **[33 Business Invariants (BR-01 to BR-33)](/docs/roles/managing#4-the-33-inviolable-business-rules-br-01-to-br-33)**. Non-negotiable architectural invariants include:
- **BR-01 Strict Multi-Tenancy**: Every database query, cache key, and file path is scoped by `org_id`. Cross-tenant reads return 404.
- **BR-02 Private Templates**: Templates are strictly private to each customer company. No public catalog or cross-company leakage.
- **BR-13 AI Proxy is the Only Path**: Workspaces hold only short-lived session tokens—never real provider API keys.
- **BR-18 Human in the Loop**: AI scores are evidence citations for a human reviewer. No auto-rejections.

### 3. Review System Architecture & Contracts
- **[System Architecture](/docs/architecture/system-architecture)**: The modular monolith backend, Sysbox workspace container orchestrator, AI Proxy, and Redis BullMQ queues.
- **[Database Visualization & Schema](/docs/database/db-visualization)**: PostgreSQL 16 schema, Citext case-insensitivity, and Row-Level Security (RLS) policies.
- **[API Documentation](/docs/api/overview)**: OpenAPI 3.1 REST contracts and shared Zod schemas (`@hs/contracts`).
- **[Business Requirements Document (BRD)](/docs/brd/overview)**: The complete 150 requirement specifications with individual acceptance criteria.

### 4. Set Up the Local Workspace
Start the standard development environment:

```bash
# 1. Start Docker dependencies (PostgreSQL 16, Redis 7, LocalStack)
pnpm infra:up

# 2. Run the Prism OpenAPI mock server for rapid local development
pnpm mock

# 3. Start all services in parallel (Fastify API, Next.js Web, Docs)
pnpm dev

# 4. Run tests and multi-tenancy validation
pnpm test
pnpm test:tenancy
```

### 5. Review Your Role Playbook
Select your team perspective using the top navigation switcher or the links below:
- **[Software Development Engineer (SDE) Playbook](/docs/roles/sde)**: Fastify API, Next.js portals, container runtime, and definition of done.
- **[AI & Evaluator Engineering Playbook](/docs/roles/ai)**: Reviewer agent pipelines, rubric evaluation, token quotas, and AI Proxy firewalls.
- **[QA & Test Automation Playbook](/docs/roles/qa)**: Multi-tenant RLS test suites, cross-tenant 404 assertions, and E2E testing.
- **[Product & Engineering Management Playbook](/docs/roles/managing)**: Product roadmap, commercial pricing, quote builder, and team governance.

## AI-DLC Documentation Governance Protocol

> [!IMPORTANT]
> HelloSmart operates under the **AI Developer Life Cycle (AIDLC) Documentation Rule**:
>
> Whenever a developer or AI coding agent modifies database schemas (`packages/contracts/db/`), changes API schemas (`packages/contracts/openapi/`), or alters service architecture, the agent **must update these docs in the same PR**.
>
> Run `pnpm docs:sync-check` to assert that zero documentation drift has occurred.
