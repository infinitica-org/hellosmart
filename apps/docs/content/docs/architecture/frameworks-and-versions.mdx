# Frameworks & Versions Matrix

This document defines the frozen technology stack, runtime versions, and architecture choices for the HelloSmart platform. Every dependency is selected based on strict criteria: **type safety, multi-tenant security, cold-start latency, and active LTS maintenance**.

## 2. Deep Architectural Rationale

### Why NestJS + Fastify instead of Express?
Standard Express lacks built-in dependency injection, relies on middleware chaining that easily leaks errors, and has significantly higher HTTP overhead. NestJS provides strict module boundaries (`AuthModule`, `TenancyModule`, `AssessmentsModule`), while Fastify delivers 2x higher request throughput and native WebSocket support for candidate terminal streaming.

### Why Drizzle ORM instead of Prisma?
Prisma requires an external binary query engine (`prisma-query-engine`) that adds 50MB+ to container images and obscures SQL generation. Drizzle is lightweight, outputs zero-overhead raw SQL, and makes it trivial to inject `set_config('app.org_id', $1, true)` into PostgreSQL transactions for RLS enforcement.

### Why Sysbox instead of Firecracker or gVisor?
1. **Firecracker**: MicroVMs provide stellar isolation, but provisioning nested Docker environments inside a Firecracker microVM takes over 35 seconds and requires nested virtualization flags not available on all cloud instances.
2. **gVisor (`runsc`)**: Traps host syscalls in user space, causing severe performance penalties (3x slowdown on disk and git operations) that degrade candidate IDE responsiveness.
3. **Sysbox (`sysbox-runc`)**: Provides secure user namespaces and allows unprivileged Docker-in-Docker natively, spinning up complete Ubuntu developer environments in under 5 seconds with zero host kernel compromise risk.

### Why Fumadocs for HelloSmart Docs?
Fumadocs is built natively on Next.js App Router and Turbopack. It provides:
- First-class MDX compilation with automated Table of Contents and frontmatter validation.
- Built-in full-text search without external Algolia dependencies.
- Native integration with our role-based authentication proxy.
